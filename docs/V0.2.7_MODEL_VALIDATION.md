v0.2.7 turns model validation into a release gate. It combines a dedicated
end-to-end scaling test with the existing media-management and accounting
tests, then writes both human-readable and machine-readable reports.

## Gate coverage

| Area | Validation |
|---|---|
| Plane scaling | Saturated write time decreases from 1 to 2, 4, and 8 planes |
| Request size | An eight-plane read exposes materially more bandwidth than one page |
| Mapping | Sequential slot use, generation safety, reverse lookup and erase reuse |
| CopyEngine | Pipelining beats serial copy and respects buffer limits |
| Host GC | Victim selection, copy traffic, erase-only fast path and watermarks |
| Refresh | Deadline selection, traffic, remap and contention paths |
| Wear | P/E-dependent failures, retirement and capacity loss |
| Resources/timing | Online utilization accounting and NAND command intervals |
| Component ownership | Shared topology, frontend lifecycle, cache LRU and policy/mechanism split |

The scaling checks deliberately use inequalities rather than exact cycle
counts. This catches broken parallelism while allowing the timing model to
evolve without rewriting golden values.

## Run the gate

```bash
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build -j
python3 tools/model_validation.py --build-dir build
```

Results are written to `results/model_validation/validation_report.json` and
`validation_report.md`. Any failed check makes the command return non-zero.
The Release/GCC CI job runs the same gate after the complete CTest suite.

## Release policy

Changes to component ownership, stripe geometry, allocation, mapping, GC,
Refresh, retirement, or statistics must pass this gate. The default
configuration must also remain behaviorally compatible with the full-device
stripe used by v0.2.6.
