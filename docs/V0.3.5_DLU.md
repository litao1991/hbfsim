# HBFSim v0.3.5 DLU Programming Model

v0.3.5 实现 HBF Write 的三层粒度：

```text
64B Host Fragment
  → 4KiB Pending Device Logical Unit
  → 4KiB NAND Page Program
```

## DLU Assembly

`DluAssembler` 按 `(Channel, Channel Local DLU Base)` 保存 64-fragment coverage bitmap。
仿真器不保存真实 payload，只保存覆盖位图和贡献请求 ID。

- Fragment 地址和长度必须 64B 对齐；
- 重复 fragment 返回 Write Status `0x2`；
- Pending DLU 上限按 Channel 独立计算；
- 第一个 fragment 按其 H2D 到达时间建立唯一 deadline；
- 只有 64 个 fragment 全部到齐才产生 NAND Program；
- 到期仍不完整时，所有贡献请求返回 Write Status `0x5`。

## Pending Write Read

Read 查询 Pending DLU 时：

- 请求范围已全部覆盖：等待相关 fragment 的 H2D 到达后从 DLU Buffer 转发，不执行 NAND Sense；
- 请求范围存在缺失 fragment：返回 Read Status `0xA`；
- 不存在 Pending DLU：进入正常 NAND Read。

## Page-0 Auto-Erase

规范 Profile 写入 dirty Block 的 Page 0 时自动形成：

```text
Erase latency + Program latency
```

Erase failure、P/E retirement 和容量损失继续复用现有 Reliability/Block Retirement
路径。研究 Profile 的显式 Erase 行为保持不变。

验证入口为 `tests/spec/test_dlu.cpp`，覆盖完整聚合、重叠、每 Channel Pending 上限、
timeout、Read forwarding、Read Pending Write 和 Page-0 Auto-Erase。
