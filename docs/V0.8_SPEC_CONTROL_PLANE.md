# HBFSim v0.8：Spec Block Replay 与控制面

v0.8 将默认 `hbf_v0_7` Profile 从“具备研究型 Host-managed 扩展”收敛为可直接执行的、Host 控制的规范路径。接口仍以 `Simulator` API 为核心：这使实验程序能够表达 Host 的决策，而无需先建模 AXI flit、CSR packet 或固件。

## 1. R1–R5 Block Addressing 与 Host Replay

`SpecBlockAddressing` 将 OCP HBF v0.7 §5.7 的 R1–R5 公式投影到当前拓扑。一个模拟 Plane 是一个数据条带 lane；因此：

- `R1` 是 Channel 内 replay lane 数；
- `R2` 是每 lane 的 Bank 数；
- `R3` 是每 Block 的 Page 数；
- `R4` 是每 Page 的 64B 单元数；
- `R5 = R1 × R2` 是 Data Stripe Width。

给定失败页地址，`SpecBlockReplayPlan` 保存失败 Block 的 page-0 全局地址，并按 `page0 + i × R5 × page_size` 给出整个 Block 的顺序重放地址。`start_host_refresh()`（或 Program Failure 后形成的 plan）会产生这份 Host-facing 计划；`start_spec_host_replay(plan_id)` 由 Host 在数据准备好后显式启动。

该路径顺序提交 Page 0 至最后一页。Page 0 仍经现有的 Auto-Erase 事件实现；不会调用 Research Stripe Mapping、`CopyEngine`、内部 GC 或自动数据迁移。若重放期间再次 Program Failure，旧 job 终止并形成新的 `SpecBlockReplayPlan`，由 Host 决定是否、何时继续。

## 2. Simulator API 控制面

`Simulator` 提供：

```cpp
HbfRegisterResult read_register(uint32_t channel, uint32_t offset) const;
HbfRegisterResult write_register(uint32_t channel, uint32_t offset,
                                 uint64_t value);
HbfAdminResult submit_admin(const HbfAdminCommand& command);
```

当前按 Channel 动态读取的寄存器包括 BUCCAP (`0x0000`)、VS (`0x0008`)、BUCC (`0x000C`)、BUCSTS (`0x0010`)、MAXPEC (`0x0144`)、AVGPEC (`0x0148`) 和 REDCAP (`0x014C`)。其中 P/E 和 Reduced Capacity 数值来自当前 Media Block 状态，而不是静态配置快照。BUCC 支持设置 WLS；`10b` 代表 Host-controlled Wear Leveling。

这是 transaction-level 接口：尚未模拟 AXI/flit 编码、sideband、credit 或寄存器访问时延。未来更细的互连模型应适配该 API，而不改变已有 Host 控制语义。

## 3. Spec Zone Remap（Opcode `0x08`）

启用配置：

```yaml
hbf:
  spec_zones:
    per_channel: <zone count>
    size_pages: <pages per zone>
```

每个 Channel 的 zones 必须等分其全部 local Page 容量。`SpecZoneManager` 保存独立的 per-Channel logical-zone → physical-zone 双射；`AddressMapper` 在后续 I/O placement 时查询该映射。

调用 `submit_admin()` 并指定 `HbfAdminOpcode::ZoneRemapping` 前必须满足：

1. BUCC.WLS 为 Host-controlled；
2. 指定 Channel 已 quiesce；
3. swap pair 非空，且每个 Zone ID 有效、不同且只出现一次。

命令只交换 L2P 映射，不复制或擦除任何数据。Host 必须使旧数据失效、在新映射的 Zone 显式 rewrite，并在完成前自行避免访问陈旧位置。这保留 HBF 的 Host-managed 责任边界。

## 4. 可执行合规覆盖

`tests/spec/test_block_replay.cpp` 检查 R1–R5 地址序列、默认 Profile 的 Host Refresh 重放及流量统计；`tests/spec/test_admin.cpp` 检查寄存器、WLS gate、Zone swap 后的新 placement、重复 Zone ID 拒绝和 per-Channel quiesce。

v0.8 的刻意非目标包括每 Zone 的 MAXPEC/AVGPEC 寄存器、完整 Reduced Capacity Admin payload、以及 CSR 的 packet/flit transport。这些功能可在保持本 API 的基础上继续增加。
