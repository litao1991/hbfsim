# HBFSim v0.4.1 Architecture Refactor

v0.4.1 冻结 v0.4.0 的协议、时序、介质和统计行为，只重构组件边界与 ownership。

## 组件边界

```text
Simulator (time, EventQueue, request lifecycle, phase)
└── HbfSystem (device composition root)
    ├── ProtocolFrontend
    │   └── Validator + AXI ordering + DLU assembler
    ├── BaseDieController
    │   └── SchedulingPolicy + MediaScheduler + InterconnectModel
    ├── NandMediaSystem
    │   └── NandTopology + Plane/Die/Bank state + BankReadCache
    ├── AddressMapper / HostRouter / ReliabilityModel
    ├── CopyEngine
    └── HostGcManager / RefreshManager
```

`NandTopology` 是 Plane、Die、Bank 展平以及 Plane→Bank 关系的唯一实现。Mapper 与
MediaSystem 引用 `HbfSystem` 中同一个 Topology。`PhysicalAddr.bank` 是 Bank 索引的
authoritative field，不再在 Simulator 中重复使用 Plane 取模计算。

`BankReadCache` 独立封装两条目 LRU、generation-aware lookup、fill 和 Page/Block
失效。`NandMediaSystem` 持有所有 Plane/Die/Bank、瞬态 Page 状态和 erased-block
materialization guard。

`ProtocolFrontend` 负责 Host 请求合法性、AXI admission/completion 和协议响应编码；
`BaseDieController` 负责命令 ready/claim、来源调度策略以及 Host/Fabric 资源。
Copy Job、Pending Recovery 和 Job ID 由 `CopyEngine` 持有，研究型 Stripe/Copy GC 源码
位于 `src/extensions/`。

## 物理目录

公共声明已从 1,513 行的 `core.h` 拆入按职责命名的窄头文件。`core.h` 保留为兼容
umbrella，生产源码改为包含直接依赖。实现代码分布在：

```text
src/kernel      src/protocol    src/controller
src/media       src/mapping     src/management
src/extensions  src/frontend    src/stats       src/config
```

## 行为冻结与验证

- Event 类型、排序规则和时间推进未改；
- Flat `Config` 字段与 YAML/Resolved Config 契约未改，避免大面积无语义 diff；
- StatsCollector 算法与 CSV schema 未改；
- v0.4.0 固定 trace 的 11 个 CSV/YAML 输出逐字节一致；
- `component_boundaries` 测试覆盖共享 Topology、Frontend ownership、Bank LRU 与调度选择；
- 全量 CTest、Spec Compliance、Model Validation 和 ASAN/UBSAN 是提交门禁。

Config 分组和 Stats Observer 留到独立后续变更；它们不应与本次 ownership 迁移混合。
