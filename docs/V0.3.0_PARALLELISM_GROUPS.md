# HBFSim v0.3.0 Parallelism Groups

v0.3.0 removes the assumption that every Host-managed stripe spans every
plane in the device. The physical media is divided into equal, contiguous
Parallelism Groups, and each physical stripe spans one block from every lane
inside exactly one group.

## Configuration

```yaml
stripe:
  scope: device  # device | stack | custom
  lanes: 0       # required for custom; optional consistency check otherwise
```

- `device` preserves v0.2.6 behavior: one group containing every plane.
- `stack` creates one group per stack.
- `custom` uses `lanes` contiguous flattened planes per group.
- The selected lane count must divide the total plane count and may not split
  a Stack boundary: a group either fits evenly inside one Stack or contains an
  integral number of complete Stacks.
- Specifying `lanes` without `scope` selects `custom` for convenience.

The resolved configuration records `effective_lanes` and
`parallelism_groups`. The summary records `parallelism_groups`,
`stripe_width_pages`, and `stripe_capacity_pages`.

## Address formula

Let `B` be blocks per plane, `W` the group width, and `P` the physical stripe
identifier:

```text
group       = P / B
block       = P % B
local_lane  = slot % W
page        = slot / W
global_lane = group * W + local_lane
```

`global_lane` is then decoded into Stack/Die/Plane using the configured NAND
topology. Reverse mapping validates that the PPA belongs to the encoded group
before reconstructing the slot and LPN.

Because overprovisioning is reserved in whole physical stripes, changing the
group width can introduce a small rounding difference in Host-visible capacity.
The total physical capacity remains unchanged and both capacities are reported.

## Allocation and failure domain

Free stripes are initialized block-major and group-minor, so consecutive
logical stripes are distributed across groups instead of filling one group
first. GC, Recovery, and Refresh may select a replacement in any group; their
CopyEngine behavior is unchanged.

Erase completion waits only for the lanes in the source group. A failed block
retires its group-local physical stripe, not every block with the same block
index in other groups. Capacity loss is therefore:

```text
group_width * pages_per_block * page_size
```

This preserves regular O(1) forward/reverse mapping while making stripe width,
GC granularity, recovery cost, and failure domain independently measurable.

Run the supplied width sweep with:

```bash
python3 tools/experiment_runner.py experiments/parallelism_group_sweep.json \
  --binary build/hbfsim --jobs 4
```

## Compatibility

The default scope is `device` and `lanes` is zero. Existing v0.2.6 configs
therefore retain the same stripe width, logical capacity, physical IDs, and
allocation order. The v0.2.7 validation gate plus the dedicated
`parallelism_group` test protect both legacy and grouped behavior.
