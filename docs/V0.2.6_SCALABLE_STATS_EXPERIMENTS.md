# HBFSim v0.2.6 可扩展统计与实验 Runner

## 在线 ResourceTracker

旧实现为每次 Array、Fabric 和 Host 占用保存 `[start,end)`，实验结束后再排序、合并和求交；内存随事务数增长。v0.2.6 把资源开始/结束表示为事件时间线上的 `+1/-1` transition，在线累计：

- busy duration；
- Array 与 Fabric overlap；
- active-plane time area 与最大并发度；
- 每 Plane、Die、DataPort、Host Channel 的 busy duration。

常驻计数器数量只随拓扑增长，不随请求数增长。资源统计窗口包含 Measurement 后为了完成 GC/Recovery/Refresh 而产生的 Drain，并由 `resource_measurement_duration_ns` 单独标识。

Queue Depth 不再记录每次变化。`statistics.queue_depth_sample_interval_ns` 控制两次样本的最小时间间隔；`0` 恢复逐变化记录。无论间隔多大，首个和最终状态都会输出。

## Sweep 描述

Runner 使用 JSON，参数名是配置的 dotted key，参数数组做 Cartesian product：

```json
{
  "base_config": "configs/hbf_baseline.yaml",
  "trace": "traces/example.csv",
  "output_root": "results/example_sweep",
  "parameters": {
    "scheduler.max_consecutive_reads": [16, 64],
    "statistics.queue_depth_sample_interval_ns": [1000, 10000]
  },
  "plot_metrics": ["p99_latency_ns", "effective_bandwidth_GBps"]
}
```

运行：

```sh
python3 tools/experiment_runner.py experiments/example_sweep.json \
  --binary build/hbfsim --jobs 4
```

工具只使用 Python 标准库。每个 run 目录包含：

- `input_config.yaml`：base config 与本次覆盖值；
- `resolved_config.yaml`：C++ Config 解析后的完整有效配置；
- 原有全部 CSV；
- `experiment_metadata.json`：Git SHA、Trace SHA-256、配置 SHA-256、参数、命令、UTC 时间、返回码和日志。

Sweep 根目录包含 `sweep_summary.csv`、`sweep_manifest.json` 和 `plots/*.svg`。失败 run 保留日志，Runner 完成其它组合后返回非零状态。相同 Git SHA、Trace hash、resolved config 和 random seed 共同定义可复现实验输入。
