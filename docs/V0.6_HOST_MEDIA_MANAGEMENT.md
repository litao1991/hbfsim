# HBFSim v0.6 Host-managed Media Management

v0.6 closes the Host-managed control loops without reclassifying them as
device-internal CopyEngine work.

## Replay and Host refresh

`ReplayPlan` remains the device indication for a Program Failure. The Host
declares reconstructed payload availability by calling:

```cpp
simulator.start_host_replay(plan_id);
```

The resulting `HostReplay` transaction transfers every non-hole page over the
Host→Device path, programs destination slots strictly in ascending order,
commits the Stripe remap only after the destination is sealed, and finally
erases the source Stripe. A destination Program Failure aborts the migration,
keeps the old mapping live, and emits a fresh ReplayPlan for a later Host
attempt. No CopyEngine read/buffer flow is used.

`start_host_refresh(logical_addr)` is the same Host-payload mechanism for a
sealed Stripe selected by policy. `refresh_required()` exposes a retention or
read-disturb indication; in a Spec profile automatic refresh does not silently
start a research CopyEngine migration.

## Zone placement and wear policy

Zones now have two distinct effects:

1. `logical_zone → physical_zone` selects the free physical Stripe partition
   for new allocation/rewrite placement.
2. Zone telemetry records writes and per-block erase samples, yielding
   `MAXPEC`, online `AVGPEC`, and sample variance.

`start_host_wear_leveling()` selects the hottest logical Zone and a lower-wear
physical Zone, changes its placement mapping, and issues Host rewrites for
sealed affected Stripes. Slot order and Stripe generation remain properties of
each allocated Stripe and are never rewritten in place.

## Reduced capacity

Block retirement continues to retire its Host-managed physical Stripe. The
Host-facing `Simulator::reduced_capacity()` report includes retired Block and
Stripe counts, usable capacities, and a physical-Stripe retirement bitmap for
placement policy. It is an API-level control-plane view; CSR/MMIO encoding is
intentionally deferred to the later Admin-control-plane iteration.

## Tests

`test_host_replay` verifies failed-program replay, remap, and source erase.
`test_zone_placement` verifies that remap affects physical Stripe selection.
`test_host_management` covers Host refresh, wear-triggered rewrite, and
retirement/capacity reporting.
