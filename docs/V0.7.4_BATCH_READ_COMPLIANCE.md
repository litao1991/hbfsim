# HBFSim v0.7.4 Batch Read Compliance

This release separates two intentionally different Batch Read policies.

| Simulation profile | Scheduler policy | Batch release condition |
| --- | --- | --- |
| `media_research` | v0.5 aggregation experiment | per-Bank timer window; `max_pages` may split an emission |
| `hbf_v0_7`, `ai_system` | OCP HBF v0.7 §5.3.2.2 | a following Regular Read; no timer and no `max_pages` split |

The Spec path treats the Regular Read command as a Base-die batch boundary.
It flushes all accumulated Batch cache-miss reads, including requests in
different Banks.  The released requests are then placed into their individual
`BankSenseQueue`s, which preserves the required strict in-Bank sense order.
The Regular Read itself follows its existing path after this flush, including
the cache-hit fast path.

`batch_hint` continues to represent the AXI Flash-I/O Read Type bit in trace
input.  For the v0.7 profile, it maps to the interface-table field
`ARUSER[2]`; `ARUSER[1:0]` remains the command-packet type.  The prose phrase
"bit 0" in §5.3.2.2 is therefore not used as the wire encoding.

The Spec does not prescribe a timer nor an implementation limit equivalent to
`max_pages`.  Both configuration values remain accepted for portable input,
but are ignored by the Spec scheduling path.  A trace ending with an unclosed
Batch Read has no Regular Read boundary and is intentionally left pending;
the trace producer must provide the boundary command.

The compliance test covers a cross-Bank batch, a deliberately large research
window, and a subsequent Regular Read.  It verifies that the boundary releases
both Bank queues before that timer could fire.
