# v0.1.1 架构收敛说明

本版本优先落实优化建议中的 P0 项，目标是提升实验可信度、可解释性和大 Trace 可扩展性，而不是继续增加 NAND 功能。

## 已完成

1. 测试从标准 `assert` 改为始终生效的 `CHECK`，Debug/Release 都执行同一组验证；
2. `EventQueue` 从 `Simulator` 的裸优先队列中抽出；
3. `FlashTransaction` 成为 `SubRequest` 的正式语义别名；
4. `HostRouter/HostRoute` 与 `PhysicalAddr.data_port` 解耦；
5. Host Interface 支持 Command/H2D/D2H 全双工或共享半双工；
6. DataFabric 同时配置 aggregate 和 per-port 峰值带宽；
7. `IRequestSource/CsvTraceSource` 逐条读取 Trace；
8. 生产执行路径采用 Initialize/Warmup/Measure/Drain，并严格排空 Warmup；
9. `image_loaded/preconditioned` 以稀疏按需方式初始化有效页；
10. 固定内存直方图输出 p50/p95/p99/p99.9；
11. 输出 transaction latency breakdown、队列深度和 Stack/Die/Plane/DataPort/Host Channel 占用；
12. GitHub Actions 覆盖 GCC/Clang、Debug/Release、ASan/UBSan。

## 兼容性

命令行保持不变。配置需要显式关注两个新假设：

```yaml
host_interface:
  full_duplex: true

internal_fabric:
  aggregate_bandwidth: 1TBps
  port_bandwidth: 64GBps

initialization:
  mode: image_loaded
```

直接调用 `Simulator::submit()` 的单元测试接口仍可使用；大 Trace 与严格 phase boundary 应使用 `Simulator::run(IRequestSource&)`，命令行默认走该路径。

## 后续边界

以下属于 v0.2/P1，不在本次改动中伪装成完整实现：Source-aware queue、Placement/Allocator/MappingTable 拆分、Reverse Mapping、Free Block Pool、GC、Automatic Refresh、磨损/坏块生命周期、Program Failure Replay 和实验 sweep/metadata 工具。当前接口已经为这些模块保留 `TransactionSource`、初始化模式和独立资源边界。
